# M6 continuation validation — 2026-11-01

This record covers the profile/semantic persistence slice added after the
M1–M5 stage reports.

## Implemented and verified

- `agentprofile.Snapshot` / `RestoreSnapshot` use bounded canonical bytes,
  sorted records, cross-entity validation and derived-index reconstruction.
- Static `agent.apply/v1` computes a private LiveControl candidate and shares
  core admission/group/P1/receipt/RootSet with domain state. `agentstore` now
  calls that dispatcher and stores no separate domain snapshot or ledger.
  Create → transitions → close → open → semantic replay was verified on native
  `DirectoryIO`.
- Reusing the same `RequestKey` after reopen returns the original typed Task
  and Execution result; a different command under that key is not accepted.
- CURRENT-before/after unknown never installs candidate roots or object
  locations. Reads stop when fenced; reopen selects the actual authenticated
  prefix and reconciles the original RequestKey. Canceling a waiter does not
  revoke an admitted Agent command.
- Mixed domain/profile commands share one CURRENT publication and retain each
  member's original Fence; dependent semantic rejection waits for predecessor
  P1. Resource rejection preserves healthy reads and prior receipt retries.
- Corrupted published profile content is fenced as storage corruption, never
  swallowed as a business rejection. A staging-only predecessor Fence cannot
  escape before publication.
- `agentstore.Reconcile` delegates to core lookup; typed retries read their
  original ACK Fence even after Goal/Step/cancel changes and reopen. Legacy
  domain snapshots are rejected explicitly, without modifying their bytes.
- `agentstore.Command` validates the closed operation union and returns one
  typed result plus the profile publication Fence.
- Local service/client `apply_agent` and `get_agent_state` use the same core,
  canonical command bytes and authenticated connection principal. Tests cover
  capability opt-in, malformed/unknown command bytes, principal injection,
  scope isolation, historical state, wrong successful response bodies and
  original RequestKey retention after response loss. CLI recovery requires
  `--agent-profile` for a log containing these transactions.
- Historical View `StateEntries` traversal authenticates the complete radix
  snapshot and every domain value before returning; the local service/client
  path preserves view ownership and limit failures never return partial data.
- `graphstore` BranchRef Fork/Advance uses durable Journal Event records,
  version CAS, reopen replay and original-proof idempotent retries.
- `graphstore.CommitJoin` publishes an explicit conflict-resolved JoinPlan and
  replays all parent/canonical checks after reopen.
- Join/Branch preview does not mutate graph before P1. Tests reject verification,
  quota and unknown-publication candidates; original typed Branch results
  survive later head advances/reopen. Replay validates Space/generation before
  any tail repair.
- `model.RootSet.Validate` and the core RootSet codec reject malformed and
  all-zero root identities while leaving slot-specific authorization to the
  enabled profile registry.
- `memory.Durable` uses prepared Journal projection: candidate state is
  private before P1, installed only after publication, and replay validates
  the complete semantic prefix before tail repair. Lifecycle and replay tests
  pass.

## Explicit boundary

LiveControl, DomainStates and CommandReceipts now share the core candidate and
publisher. Knowledge, memory and graph/BranchRef adapters still own separate
projections. Remaining M6 work includes their core root integration, complete
Invocation/Activity/message/Continuation lifecycle, historical Node queries,
retention/maintenance and final support/protocol acceptance. The current Agent
projection is a bounded whole-partition snapshot with O(n) conversion; these
tests do not establish large-task performance or device power-loss durability.
