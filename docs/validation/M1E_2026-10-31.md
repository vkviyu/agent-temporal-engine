## 根库与 CLI 实际跨段往返

使用根库 Create，SegmentTargetBytes=1024、MaxCount=8、MaxDelay=1s，8 个 goroutine 同时提交不同 RequestKey 的 Mutate：

1. 8 笔事务跨越 **31 个物理段**，但物理 publication Generation 只增至 **1**，全局 LSN=8。
2. Close/Open 后全部值相同，8 份 LookupResult 与各自原 Ack 全字段相同，保留 8 个不同成员 LSN/proof。
3. 在实际独立项目运行 `go run ./cmd/ate recover-state DIR`，默认 writer 目标无需与创建时相同；返回 semantic_replay_verified=true、generation=1、last_lsn=8、tail_bytes=0，RootSet 与库 Snapshot 一致。
4. 实际 CLI `version` 为 `agent-temporal-engine 0.1.0-dev.m1e`。

本次实例 RootSet：`55c7587c544ac646db3a87608a09f16f579696a2cbb66001e9b6879a410d5468`。随机 TxID 和并发顺序使其不是跨运行固定向量；验收依据为同次运行的原 Ack、重开结果和 CLI 恢复一致。

## 范围

M1e 没有改变进程内 admission 的持久性：P1 前进程退出仍需用原 RequestKey 对账。没有实现 reader pins、服务/SDK、checkpoint/compaction、Revision 图或 Fork/Join。当前恢复仍读取完整发布历史，保留全部段句柄到关闭，未测吞吐/恢复耗时上限，也没有设备断电认证。下一阶段 M1f 见 [当前状态](../M1E_STATUS.md)。
