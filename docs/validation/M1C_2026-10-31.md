## 本次审计发现与修复

1. 已 ACK 对象被篡改为 refcount=4097 时，解码返回 ObjectLimit；旧逻辑将其当请求配额拒绝，仍可输出 Snapshot。已通过专用来源标记修复：存储内容错误不走 admission 资源分支，并有真实失败 repro 转回归。
2. 普通 ReaderAt EIO 不证明内容已经损坏；保留 IO 原因、拒绝后续输出，不添加虚假 Corruption 结论。短 EOF 则表示已发布对象范围缺失。
3. 未知 Method/radix Version 在恢复中按未知必需 schema 拒绝，避免旧 reader 把可升级格式误叫损坏。
4. 根包导入与新 state 包纳入依赖 guard：cmd→root→engine，state 只依赖 codec/model，storage 不反向 import engine。

## Go 库与 CLI 实际往返

在独立临时目录执行 `go run ./cmd/ate init-state DIR`，随后使用根 Go 包：

1. `ate.OpenExisting`；Mutate 写入 `space=smoke`、`key=hello`、bytes 值 `durable`，RequestKey 为可信宿主提供。
2. Close/Open；LookupRequest.Result 与原 Ack 全字段相同；再次 Mutate 返回同一 Ack；GetState 读出 `durable`。
3. `recover-state DIR`：LSN=1、published_bytes=2296、semantic_replay_verified=true，RootSet 与原 Ack 相同。
4. 对同目录运行 `recover-journal DIR`：相同 LSN/CommitDigest，但明确 semantic_replay_verified=false。

本次实例的 StateRoot 为 `884ba16c9d958be9f65c50455e3d08e2c2b96b3a3621041549fdc88823f85792`；receipt/RootSet 包含随机 TxID，不能把单次值当跨运行常量。原 Ack/Lookup/重试三者严格相同。
