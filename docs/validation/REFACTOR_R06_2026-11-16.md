# R06：逻辑 policy 依赖与物理引用分型

日期：2026-11-16。结论：R06 完成，后续按[主计划](../ATE_REFACTOR_MASTER_PLAN.md)推进 R07。

## 语义决定

现有 policy 以 Space 内的 digest 为身份，不是物理对象地址。相同 digest 的不同 namespace、不同已授权 owner 共用撤回结果；Space 之间隔离。owner 的历史源解析与授权必须在 policy 聚合之前完成，policy identity 不授予读取权限。

本次保留上述行为。FactualCorrection/UseBan 允许审计、拒绝新复用；PrivacyErasure/ACLRevocation 同时拒绝历史披露与复用。kind 用于依赖构建和物理读取边界，不改变撤回范围。不修改 Memory、derivation、checkpoint 或公共协议的持久化 schema，不引入旧格式兼容。

## 实现

- `engine/policy_dependency.go` 定义带 kind 的内部依赖，以及唯一含义明确的 `policyIdentity`/`policyIdentities` 转换边界。转换保持 ID 顺序、重复项和空项，后续 policy closure 仍按现有方式规范化。
- Knowledge Observation/Packet/Summary 的构建器保留 payload kind；无法由完整领域记录确定的 selector 保留为逻辑 node，不猜测为物理地址。packet goal 对同 digest 多种 payload namespace 的歧义也保持逻辑身份。
- Node、TaskTrace、Annotation、Investigation、Graph 的混合依赖在构建时区分逻辑记录、control/revision/node selector 和真实内容。`NodeObject` 是目录选择器，也可选择内嵌 Knowledge 记录，不能据此直接读取物理对象。
- `verifyContentClosure` 只接受 `physicalObjectReferences` struct，普通 `[]model.ObjectID` 或 policy dependency 不能隐式传入。五个生产调用点均在 Graph/Knowledge/Summary 的 `ContentReferences` 提取器处显式构造；遍历仍遵守原先的对象认证、限额、去重和取消规则。
- `memory.AccessPolicy` 与 persisted derivation 的注释明确 digest identity 契约。已经完成解析的 policy ID 列表继续用于现有 delivery/closure 接口，没有把全库所有 `ObjectID` 改名或分型。

物理引用构造器是包内显式信任边界，并非对任意手工构造代码的静态证明；调用者仍须使用领域 schema 提取器。本次回归验证了实际生产路径，不宣称所有裸对象读取 API 都已改成强类型。
