# R08：TailReject 与认证布局 cleanup

日期：2026-11-16。当前状态：已完成。

## 目标

R08 明确 `TailReject` 的实际行为：它拒绝修复 active tail 和 ordinary orphan，但不是完整只读检查。完成完整 authority、published prefix、semantic replay、compaction source 和 orphan 验证后，仍可以清理已经认证的 compaction residue 和 `RetiredSegments`。

当存在 compaction intent 或退休布局时，恢复必须先稳定当前 publication 的根目录目录项，再执行任何会删除旧布局的操作：

```text
完整验证
→ collectOrphans
→ SyncDir(".") stabilization barrier
→ compaction intent / RetiredSegments cleanup
→ TailPolicy
→ final Ready witness sync
→ PublicationSynced=true
```

没有 compaction intent 且没有退休描述符的普通 active tail 不增加这次额外根目录同步。

## 实施

`storage/recovery.go` 在 `collectOrphans` 成功后加入 stabilization barrier。条件为存在 compaction residue 或 `m.RetiredSegments`。barrier 失败时返回 `ErrRecoveryIncomplete`，保留 `RecoveryReport`，不清理 compaction intent、不删除退休 segment、不执行 tail refusal，也不设置 `PublicationSynced`。

最终 Ready witness 仍然是独立的最后一次 `SyncDir(".")`。成功执行 stabilization 只能证明 cleanup 前的当前 publication 已稳定，不能授予 Ready；TailReject 因 tail/orphan 返回 `ErrRecoveryRequired` 时，`PublicationSynced` 仍为 false。

## 修复前缺陷

一次 compaction 可以先完成 `ReplaceAtomic(CURRENT)`，再在根目录同步前失败。此时进程内可以看到新的 CURRENT，但 durable CURRENT 仍可能是旧布局。若 TailReject 随后删除 `RetiredSegments`，进程再次崩溃后会恢复旧 CURRENT，而旧 CURRENT 依赖的 segment 已被删除，最终报告：

```text
published store data is corrupt: segment: file does not exist
```

该窗口同样适用于后续普通 publish 或 recovery checkpoint 继承退休布局的情况。

## 回归覆盖

`storage/tail_reject_contract_test.go` 覆盖 TailReject 的完整组合契约，包括 active tail、ordinary orphan、malformed recognized intent、unknown intent、compaction candidates、RetiredSegments、prefix corruption、source corruption、replay failure、重复拒绝和后续 TailQuarantine。

`storage/tail_reject_cleanup_test.go` 覆盖 cleanup fault，包括 candidate、intent、retired segment 删除失败，目录同步失败，文件关闭失败，owner 关闭失败，FILE → OWNER 顺序，crash/reopen，以及 active tail/orphan/malformed intent 的保留语义。

`storage/tail_reject_publication_test.go` 覆盖：

1. compaction 在 CURRENT replacement 后、root sync 前失败；
2. tail、orphan、tail+orphan 三种组合；
3. stabilization barrier before/after failure；
4. orphan validation 在 stabilization 前失败；
5. final Ready sync failure；
6. checkpoint 和 ordinary publish 继承 retired layout；
7. checkpoint/ordinary publish 与 tail、orphan、tail+orphan 的六组崩溃场景；
8. 多次 reopen 后 durable CURRENT、历史事务和文件树保持一致。
