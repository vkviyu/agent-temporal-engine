## 实现契约

- 独立 `observation` 包只依赖标准库。engine、state 和根 ate facade 可依赖它；storage 不新增观测依赖，engine 复用 storage 已有报告。
- `observation.New(0)` 返回 nil，无分配；nil 和零值 Collector 均关闭。关闭时 Start 不读取时钟，mailbox 不分配、不创建 goroutine。这里的无分配指观测 mailbox 路径，不代表 Engine 的业务操作本身无分配。
- 正容量创建固定 ring，容量范围 1–4096，超限返回 ErrCapacity，不静默放大。启用后 Emit/Drain 不为事件分配内存。
- Emit 使用 `sync.Mutex.TryLock`，竞争立即丢弃；获得锁后若队列已满，丢弃新事件。满队列与竞争分别以原子生命周期计数器累计，通过 Drops 读取。计数不会随 Drain 重置；并发读取两个计数不是事务快照。
- 宿主主动调用 `Drain(dst)`，最多复制 `len(dst)` 条事件。并发 Drain 安全，但调用者须使用不同目标缓冲区；消费者之间可等待 mailbox 锁，生产者不等待。每次持锁复制量最多 4096 条。
- 不运行用户 callback，不引入观测 worker goroutine，不传播用户 context sink。没有 flush、可靠送达或 observer shutdown 协议。宿主停消费、消费代码失败，不影响提交结果；宿主消费逻辑在库之外处理。
- Collector 不应复制或在使用中重新初始化。可以给多个 store 共享同一指针，但事件无法区分 store、principal 或 request；需要区分时由宿主使用不同 Collector。
- Event 只有类型化枚举、数值和布尔值，没有内容、keys、IDs、原始 error、字符串标签或任意对象。
- 观测为有损诊断，不参与 admission、发布、恢复或输出授权决策，不构成第二份状态 authority。丢事件后不能依靠事件流重建操作历史或推算精确总量。

根 facade 的 Options 是 engine.Options 的别名，新增 Observation 指针完整可用。打开失败时指针仍由宿主持有；目录打开失败由 facade 发一条失败事件，进入 engine 后由 engine 发事件，不重复报告一次 Open。

```go
collector, err := observation.New(256)
if err != nil {
    return err
}
store, report, openErr := ate.OpenExisting(path, ate.Options{
    Observation: collector,
})
_ = report
var events [64]observation.Event
n := collector.Drain(events[:]) // openErr != nil 时仍然可读
_ = events[:n]                  // 宿主在库调用之外处理
_ = store
_ = openErr
fullDrops, contentionDrops := collector.Drops()
_, _ = fullDrops, contentionDrops
```

## 接入边界与计数口径

| 事件                    | 边界与计数                                                                                                                                                                                                                                         |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create / Open           | engine 公共创建/恢复边界；Open 的 Count/Bytes 复用 RecoveryReport.ScannedTransactions/PublishedBytes。Certified 复用 CheckpointTransactions，Replayed 计成功的语义 replay 调用。CheckpointHit 能表达空 checkpoint 命中。失败时报告字段可能不完整。 |
| AdmissionWait           | 请求被接纳排队至 coordinator 获得 writerMu；包括 batching、前序发布和 writer gate 等待。每个实际 flight 计一次；重新入队重新计时。receipt 快速返回和附着到既有 flight 的 waiter 不产生新的排队事件。                                               |
| Prepare                 | coordinator 的 prepareBatch 整体耗时，包含验证、编码及私有 staged 接受；不包括 beginBatch。Count/Bytes 是该次计划保留的已准备事务数/编码字节。无可发布事务为 Skipped；这不是每个请求的拒绝原因。                                                   |
| P1                      | 实际 Journal.PublishPreparedBatch 调用耗时和 outcome，Count/Bytes 为批内准备事务数/编码字节。不包含随后的 engine install。                                                                                                                         |
| Commit                  | 公共 Commit 的返回 outcome 和总耗时，包括取消等待。委托 Commit 的 typed 写入口被覆盖；在进入 Commit 前就失败的编码/参数检查不保证有此事件。                                                                                                        |
| Fence                   | stopAdmission 接收到 fenced/unknown 原因并首次进入相应终态时记录类别；Unknown 和 Corruption 优先保留原因分类。                                                                                                                                     |
| Checkpoint / Compaction | 公共维护边界整体耗时和 outcome。Compaction 的 Count/Bytes 复用 retired segment 数和 copied bytes。私有 audit verifier 与 staging 关闭 collector，不冒充另一次外部 Commit/P1。                                                                      |
| Read                    | 一个成功建立的公共 read cut 的对象读取汇总；Count/Bytes 是源 reader 成功返回的对象次数和编码字节，不是去重对象数。Outcome 反映对象 reader 错误，不代表整个读取 API 的授权/业务 outcome。                                                           |
| Scan                    | state Entries/EntriesWithPrefix 显式传入 ScanLimits.Observation 时，按现有 scanReader 汇总源 reader 成功读取次数和字节；包含已读到、随后因字节预算被拒绝的对象。GetViewEntries 已传入 engine collector。                                           |
| Cache                   | TaskTrace evidence/profile 两个 cache 的 hit、miss、insert、eviction、clear。Count 为当时 cache entry 数；RetainedEstimate 直接复用已有 bytes 计数，不为观测重新扫描值。                                                                           |
| PinWait                 | waitViews 和 CloseView 真正需要等待时的耗时/outcome，Count 为开始等待时的 outstanding owner 数。它不是底层 storage 所有 pin 的全局数量，也不计无等待的获取。                                                                                       |
| Close                   | engine CloseContext 调用的整体耗时/outcome；重试是另一条事件，不包含 facade 的 directory handle Close 时间。                                                                                                                                       |

Read 与 Scan 可以覆盖同一次对象读取，不能相加当作总 IO。Open 的物理扫描与语义 replay 分开报告，checkpoint 只跳过已认证的语义前缀，不改变物理 scan。

RetainedEstimate 只描述两个 cache 的既有预算估计，不是总 heap、RSS、全部常驻索引、checkpoint 峰值内存或 eviction 后仍由活跃读者持有的内存。未调用 runtime 内存扫描，也未为每个事件扫描全量状态。

单请求成功且未丢事件的顺序为 AdmissionWait → Prepare → P1 → Commit。并发请求、提前拒绝、调用者取消和批内不同结果不承诺此线性顺序；共享 collector 无主体关联能力。

## 低开销基准

每种模式运行 3 次，以下列出范围。测试运行于共享开发机，耗时波动明显，不据此宣称启用观测更快或计算稳定百分比。

| 基准                                              | 模式     |  ns/op 范围 |        B/op | allocs/op |
| ------------------------------------------------- | -------- | ----------: | ----------: | --------: |
| Mailbox（Start + Finish，enabled 每 64 次 Drain） | disabled | 4.516–6.053 |           0 |         0 |
| Mailbox                                           | enabled  | 90.76–121.9 |           0 |         0 |
| Mailbox                                           | full     | 116.1–246.1 |           0 |         0 |
| 真实公共 GetState                                 | disabled | 31123–53336 | 13339–13345 |       211 |
| 真实公共 GetState                                 | enabled  | 28964–55902 | 13389–13395 |       212 |
| 真实公共 GetState                                 | full     | 27013–44953 | 13388–13394 |       212 |

Mailbox 测量包含计时与发送，enabled 包含摊销 Drain；full 预先填满且不消费。真实读取启用时额外分配一个对象计数 wrapper，约 48 bytes/读；默认关闭不创建该 wrapper。真实读取原有业务分配保留，不能将 mailbox 的 0 allocs/op 推广为整条 Engine 路径。

没有独立的改动前 worktree 对照，不能声称 disabled 相对改动前完全无成本。
后续核验已将 prepare 失败时仅用于读取观测 outcome 的锁操作置于 Enabled 分支，
禁用时不新增该次锁获取；此调整纳入联合验证。

## 未覆盖边界

- 当前无已知未修复的测试失败；全库 full/race 的源码指纹、环境 skip 和首次超时记录见联合批次。
- 没有给所有公共方法逐一加 outcome，也没有为所有内部 state scan 传 collector；内部扫描落在公共 read cut 内时只进入 Read 汇总，私有 reducer/audit 扫描不单列 Scan。
- state 独立扫描错误分类只依赖其自身错误与 context，不向上依赖 engine/storage 来细分所有错误。
- 没有为 storage 直接调用者提供 collector；storage 物理 scan 仍按事务报告，未新增物理对象总数、每次 syscall 字节或逐阶段磁盘计时。
- 未穷举所有 prepare 拒绝/冲突分类、每个 maintenance 故障注入点、CloseView 各种 pin 竞态、checkpoint 不支持 schema 的观测分支；现有相关回归通过不等同于这些分支的事件断言已覆盖。
- cache 观测计数通过实际 cache 操作测试，未新增完整复杂 TaskTrace 工作负载的事件 oracle；已有 cache 回归另行运行。
- mailbox 并发 Drain 与生产者竞争在独立包测试；真实 engine 停消费测试验证满队列场景，未把所有并发 Drain 组合逐项叠加到所有 API。
- 未测长时间压力、Linux、外部断电 durability、观测下的完整 commit 性能分布，未估算总常驻内存。本轮基准是 mailbox 和真实公共读取的局部基线。
- 消费者失败不进入库，因此没有 callback panic/reentry 测试；API 结构上不接受该类 callback。宿主自行管理消费端生命周期与错误。
