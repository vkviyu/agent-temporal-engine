# R07：publication staging 元数据生命周期

日期：2026-11-16。结论：R07 完成，后续按[主计划](../ATE_REFACTOR_MASTER_PLAN.md)推进 R08。

## 实现与契约

`storage.Maintain` 在独占 owner lock 下完成整个检查，再执行显式请求的删除。零值 `RetentionPolicy{}` 只检查；新增 `DropPublicationStaging` 允许回收已认证、未选中且不被保留证明引用的 `.STAGE.*`、`.CURRENT.*` 和过期最终 manifest。`DropQuarantine` 保持独立选项。

报告增加排序的 `SelectedMetadata`、`RetainedProofMetadata`、`StagedMetadata`、`UnknownMetadata`、`RemovedStagedMetadata`，以及 `PublicationReclamationBlocked`、`ReclamationBlockers`。原有 `PublishedSegments/PublishedManifests` 明确为物理文件前缀计数，不代表权威发布数。

检查先认证 CURRENT → IDENTITY → selected MANIFEST，再检查 manifest canonical bytes、名称/ID/store 绑定及 generation 递减的来源闭包。selected manifest、LayoutSource、checkpoint source、有效 pending compaction intent 的来源均被保留。过期候选引用的来源也保留到后续轮次，确保删除中断不会让尚存记录失去证明。

发现未知、残缺、foreign、非规范或无法证明来源的元数据时，保留文件并阻止全部 publication 元数据删除。未选中的 checkpoint 流没有独立归属证书，因此作为 unknown 保留并阻止回收；不通过文件名前缀推断可删除。

删除前先同步 `manifests` 和根目录，使当前观察到的 CURRENT 命名空间稳定。否则，发布进程可能在替换 CURRENT 后、同步根目录前退出，后续删除旧 manifest 再崩溃就可能留下指向已删除 manifest 的旧 CURRENT。维护不重写 CURRENT/IDENTITY/manifest 字节，也不选择新的发布。

删除后同步目录；即使重试发现目录已空，也仍同步，覆盖上次删除成功但同步失败的情形。文件关闭失败通过 `CleanupError` 保留 FILE → OWNER 顺序，文件清理完成前不释放独占 ownership。

## 限制

维护检查元数据证明，不执行 journal semantic replay，不验证 checkpoint 流内容，也不删除 segment/checkpoint。checkpoint 分类可以包含被引用但缺失的路径，不能将报告视作存储健康认证。

扫描上限为 16,384 个目录条目和累计 64 MiB 元数据读取。`DurableIO.List` 仍不分页，单次底层 IO 不能被中途取消。未知证据可能持续阻止回收；过期证明链可能需要多轮维护。这些保守边界保留，不以自动删除未知文件换取回收率。

153 个集成场景使用已有 faultIO 模型，不是设备掉电认证；未覆盖 genesis 初始化或发布故障与维护故障的全组合笛卡尔积。实际本机文件系统基础维护测试随 storage 全套运行。
