# R25 逻辑配额与实际磁盘空间第一阶段收口

日期：2026-11-18。本阶段整理 ATE 的逻辑 published quota、segment 物理文件
开销、checkpoint、staging、retired layout、quarantine 和 maintenance metadata
边界。目标是避免把逻辑 stream offset 或文件长度误报成实际 filesystem block
占用；没有新增未经产品约束的目录级 quota，也不提交 Git。

## 已有逻辑配额

`storage.JournalOptions` 的 `MaxPublishedBytes` 和
`MaxPublishedTransactions` 约束已发布 canonical journal history。发布前
`Engine.checkPrepared` 和 `journalWriterState.validatePreparedBatch` 都会检查
归一化后的限制，超过限制时在物理写入前拒绝。

逻辑 `Publication.PublishedEnd` 是初始 segment header 加 canonical frame
stream 的 logical offset，不包含：

- successor segment header；
- sealed segment footer；
- manifest、CURRENT 和 IDENTITY；
- checkpoint 文件；
- compaction 新旧布局同时存在的副本；
- staging、retired、orphan 和 quarantine 文件。

因此 `PublishedEnd` 只能作为逻辑已发布字节的 authority，不是目录大小。

## 已确认的物理文件类别

segment 文件还包含固定 header/footer 和 rotation 布局开销。当前定义包括：

- 初始 segment header：96 bytes；
- successor header：160 bytes；
- sealed segment footer：160 bytes。

AuditFull compaction 的 `CopiedBytes` 表示复制的 logical frame bytes，不表示
candidate segment 的完整物理长度，也不表示 compaction 期间旧布局和新布局同时
存在时的目录峰值。

checkpoint 有独立的 `MaxRecoveryCheckpointBytes` 限制和
`checkpoints/CHECKPOINT.<id>` 文件。checkpoint 不增加 `PublishedEnd`，也不会
自动纳入 published quota。

staging、retired 和 quarantine 也拥有独立生命周期：

- publication staging 包括 `.STAGE.*`、`.CURRENT.*` 和临时 manifest；
- retired segments 受 reader pin 生命周期影响；
- quarantine 保存 tail、orphan 或 compaction evidence；
- `MaxUnpublishedLayoutBytes` 是 recovery 输入限制，不是长期目录 quota；
- `MaintenanceReport` 当前报告路径类别、数量和 blockers，不报告所有文件的
  byte sum。

## 当前判断

R25 以“逻辑配额与物理文件长度边界已收口”完成第一阶段：

- 现有逻辑 quota 的适用范围清晰，不能扩展解释为整个目录的空间上限。
- 可以安全报告 published logical bytes、segment file lengths、checkpoint file
  lengths、staging/quarantine file lengths 和 retired layout 的分类结果。
- 这些 file lengths 仍不是 filesystem allocated blocks、稀疏文件实际占用、写放大、
  page cache 或设备保留空间。
- 当前代码没有跨平台、可靠的 filesystem block accounting；在没有明确物理预算
  和平台契约前，新增目录级 quota 会把 retention、pin、checkpoint 和 crash
  evidence 生命周期混入一个未经定义的拒绝条件。

因此本阶段不新增 production `DirectoryQuota` 或将 checkpoint、quarantine、
staging 和 retired segments 强行纳入 `MaxPublishedBytes`。如果未来需要物理
预算，应先定义平台范围、统计口径、retention/cleanup 责任和 ENOSPC 行为，再
增加只读 inventory 与独立拒绝策略。
