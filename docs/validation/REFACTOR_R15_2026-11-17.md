# R15 大 Agent 状态有界读取验证

日期：2026-11-17。R15 为 Agent record-only 状态增加独立的 canonical record 分页读取，
保留原有完整 `GetAgentState`。本报告只记录当前实现的分页契约和定向证据，不把分页前
完整 catalog 认证误称为 R20 的按需物化。

## 契约

- 单页 JSON body 上限为 8 MiB，最多 256 条 record；`Limit=0` 使用 256，不开放可变
  byte budget。
- 第一页可以省略 `Anchor`，服务捕获当前发布位置；后续页必须携带第一页返回的完整
  durable anchor。并发新发布不会改变既有分页结果。
- continuation 绑定版本、认证主体、Space、anchor、RootSet、LiveControlRoot、
  record catalog envelope、总记录数/总字节数、有效 limit 和固定页上限。它是一致性
  cursor，不是签名授权凭证。
- 每页完整读取并认证 record catalog，重建完整 Snapshot，重新检查当前 disclosure
  policy，再输出当前页。撤回可以使后续页拒绝，即使被撤回内容不在当前页。
- `Catalog` 是 LiveControl 分区中的 record-root envelope object ID；空分区返回固定
  anchor/root 信息但 `Found=false`、空 catalog、零计数和空页。已存在的空 image 可以
  用非空 catalog 表示。
- SDK 的 `ReadFullAgentState` 聚合所有页，检查跨页 metadata、record key 顺序、数量、
  字节和 continuation，再用 `DecodeRecordImage`、`CheckScope` 和完整 Snapshot 校验。
  聚合内存仍随完整状态增长。

## 变更范围

- `api`、`protocol`、`engine`、根 facade、`service` 和 `client` 同步新增分页 DTO、
  read-delivery 路径、wire 方法、能力 `agent/record-read-v1` 和 SDK 聚合。
- wire 请求不携带 Principal，由已认证 session 注入。
- `GetAgentState` 仍受 16 MiB 完整 frame 上限约束，超限返回 `ResourceLimit`，连接
  保持可用。
- 新记录页使用已有 record image 的完整认证；没有新增持久格式、第二份 recovery
  authority 或 runtime legacy reader。

## 限制与后续

首版每页仍完整物化和认证 catalog，解决的是输出 frame 上限；分页前对象读取和状态
物化成本仍属于 R20。continuation 没有签名，不能对不可信服务端提供 Merkle 级防伪
证明。真实完整状态重组需要客户端内存与状态规模成正比。三个真实模型评估、Linux
ext4 外部 durability 和设备掉电不属于本项证据。

本项本机验证已收口；不提交 Git。
