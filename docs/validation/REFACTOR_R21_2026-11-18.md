# R21 provenance/disclosure 闭包第一阶段基线验证

日期：2026-11-18。本阶段测量历史 provenance/disclosure 闭包中的重复
projection、遍历和 JSON 解码成本，并用真实 Directory Engine 读路径确认完整
output gate 的量级。没有修改生产 cache、授权检查、reader、pin 或 delivery
grant，也不提交 Git。

## 范围和测量口径

- `BenchmarkR21SummaryProvenanceProjection` 构造 8/32/128 层 Summary
  provenance 链，并测量当前 `summaryPolicyDependencies` 与显式 parent 展开
  的投影成本。该 fixture 是内存 projection，不执行 state IO、历史 root
  认证或当前 policy Check。
- `BenchmarkR21NodeDisclosureJSONDecode` 构造 Summary、ContextPacket 和
  Annotation 三类 JSON node payload，测量 `nodeDisclosureDependencies` 对
  payload 的重复解码和依赖投影。
- `BenchmarkR21DisclosurePayloadShapes` 分别固定测量三类 payload，确认
  Summary、ContextPacket 和 Annotation 的解码常数不同。
- `BenchmarkR21EngineDisclosureReads` 复用真实 Directory Engine 的 32、256、
  1024 state record fixture，调用公开 `GetNode` 和 `GetNodeContext`。fixture
  构造、View 打开和首次预检不计入 benchmark；每个 warm 子基准先执行一次读
  再开始计时。
- `B/op` 是每 op 累计分配，不是峰值 RSS。projection fixture 的
  `fixture-json-B` 是输入 JSON 总量，不是设备磁盘占用。R21 没有把
  observation 的 Read/Scan 相加伪装成单一 IO 数字。

## 正确性 preflight

正式前置命令：

```sh
go test ./engine -run '^(TestNodeDisclosurePolicyAnnotationOrder|TestNodeDisclosurePolicyPacketAndMalformedRecords|TestNodeDisclosurePolicySummaryNamespacesAndSorting|TestNodeDisclosurePolicyPayloadNamespaces|TestSummaryCoreCurrentWithdrawalGatesReuseAndHistoricalDisclosure|TestSummaryCoreCurrentWithdrawalGatesRawGenerationOutput|TestSummaryCorePublicationReceiptHistoricalVisibilityReopenAndCompaction)$' -count=1
go test ./engine -run '^$' -bench '^BenchmarkR21' \
  -benchmem -benchtime=100ms -count=3 -cpu=1
```

preflight 覆盖：

1. Annotation、ContextPacket、Summary 的 policy dependency namespace 和
   malformed payload fallback；
2. Summary 当前撤回后的 reuse/disclosure 重新检查；
3. raw generation output 在 privacy/use-ban 语义下的历史读取；
4. Summary publication 在 reopen 和 AuditFull compaction 后保持稳定；
5. benchmark fixture 的 nested Summary、三类 JSON payload 和真实 Engine
   Node 读取均返回非空、可验证的依赖或 DTO。

两条命令均退出 0。没有执行全库 full/race；本阶段没有生产代码变更。

authenticated root 加载。

## 当前判断

当前证据支持以下判断：

- Node disclosure projection 的重复 JSON decode 是可见成本。1024 records
  的三类 payload fixture 达到约 19–20ms/op 和约 9.74MB/op 累计分配；
  Summary payload 单类的成本高于 ContextPacket，Annotation 居中。
- Summary dependency projection 的单次纯内存成本较低，但依赖数量随链深和
  fan-out 增长；真实 `summaryDependencyIDs` 还会额外支付每个 Summary 的
  state.Get、object/value 读取和 DecodeSummary，因此不能用纯 projection 数字
  直接替代完整历史读成本。
- 真实 `GetNode` 与 `GetNodeContext` 在 1024 records 下都支付约 10MB/op
  累计分配，说明小输出或局部 context 请求仍承担完整 catalog 物化成本。这个
  现象与 R20 的 page=1 基线一致，R21 没有证明可以通过 disclosure cache
  消除 catalog 物化。
- 当前最安全的优化边界仍是结构事实：已认证 root、Space、历史 anchor 和
  对象身份下的 immutable decoded projection 或 traversal result。它可以减少
  重复读取、遍历和解码，但必须在 delivery 前重新根据当前 policy 执行 Check。
- 不能缓存 `AccessPolicy.Check` 结果、`policyDependencyIDs` 的授权结论、
  reader、pin、session 或 final delivery grant。撤回后现有 correctness
  preflight 已验证历史 disclosure/reuse 仍重新受当前 policy 约束。

本批没有足够证据立即引入跨调用结构 cache。下一阶段若继续，应先增加真实
Knowledge selected View、nested Summary state records、Annotation citation
和 Investigation citation 的 authenticated fixture，并分别记录 cold、warm、
reopen、withdraw 和 AuditFull compaction 后的 Read/Scan 数量。只有当重复
state IO 和 DecodeSummary 的占比高于 cache 的常驻成本时，才设计按
`(space, principal, authenticated root, historical anchor, object identity)`
绑定的结构事实 cache。
