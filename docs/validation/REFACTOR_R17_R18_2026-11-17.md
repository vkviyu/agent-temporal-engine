# R17/R18 Graph 容量基线验证

日期：2026-11-17。本阶段只建立 Graph R17/R18 第一阶段的容量基线和
可复现语义预检，不修改生产代码、主计划或其他工作区，也不提交 Git。变更文件为
[`engine/graph_r17_r18_benchmark_test.go`](../../engine/graph_r17_r18_benchmark_test.go)。

## 范围和构造

- R17 测量 domain root membership 的 current、early 和 miss 三类结果，目标
  domain publication history 为 16、256、1024；256 和 1024 tier 因真实 publication
  fixture 构造成本过高，正式 benchmark 缩小为 64 和 128，并保留 tier 名称记录。
- R18 descendants 测量 deep、wide、shared 三种 revision 图，以及每种图的完整
  page 和 `page=1`；另测包含 128 个 disconnected unrelated revisions 的
  `page=1`。原计划的 1024 unrelated fixture 在正式校准中构造成本过高，已缩小并
  记录。
- R18 join 测量稳定可重复的 `PlanGraphJoin`，覆盖 8 和 128 entries，以及
  no-conflict 和 conflict。large=1024 在正式校准中构造成本过高，已缩小为 128；
  join fixture 本身的 revision、branch 和 state 均通过真实 publication path 建立。
- fixture 只通过公开 API 构造：`engine.Create`、`Mutate`、`ApplyGraph`、
  `OpenView`、`GetViewEntries`、`Snapshot` 和图查询 API。图 revision 的 ID 和
  entry canonical bytes 通过公开 `graph.BuildRevision`、`graph.EncodeRevision`
  计算。benchmark 没有写入 `e.history`、`e.index` 或其他私有存储结构。
- state entries 通过带 publication fence 的 historical View 读取，确保 early
  root 来自已认证历史 cut。descendants 的历史 anchor 在加入未来 child 前捕获，
  preflight 验证 anchor 不返回未来 revision。
- setup 和 correctness preflight 都在 `ResetTimer` 前完成。每个 benchmark 调用
  `ReportAllocs`。R18 查询通过公开 observation collector 报告一次代表性查询的
  object reads、read bytes、scan objects 和 scan bytes；R17 AddRevision 的内部
  `cursorReader` 不暴露给公开 benchmark，因此不伪造 object-read 数，文档明确标
  记为未计量。

## correctness preflight

每个 fixture 在计时前执行与其场景相关的语义检查：

1. R17 current 和 early revision 的读取成功；miss 的 AddRevision 被
   `graph.ErrStateUnverified` 拒绝。
2. R17 forged entries、跨 space revision visibility 和跨 space parent 均按现有
   错误语义拒绝。
3. descendants 完整结果的 node/edge 数与 fixture 图一致；`page=1` 返回单页并
   保留 continuation；历史 cursor anchor 只返回 anchor cut 可见的 revision。
4. join 的 no-conflict/conflict 计划结果数量正确；unknown resolution、forged
   entries 和跨 space join 均拒绝。

代码。
