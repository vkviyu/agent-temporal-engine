# R20 Node/View/Content 查询物化基线验证

日期：2026-11-17。本阶段测量 Node、View、Content 查询在分页前的物化、
对象读取和历史 View 成本，不修改生产查询、catalog、continuation、disclosure
或对象读取实现，也不提交 Git。

## 范围和测量口径

- `BenchmarkNodeR20Queries` 使用真实 Directory Engine 和公开 API 构造
  content state fixture，规模为 32、256、1024 条 state records。
- 每个 fixture 先发布初始 state，再发布一次更新；current View 和固定历史
  anchor View 都通过 `OpenView` 建立。计时前完成 fixture、View、entries、
  continuation 和 content digest 预检。
- 测量 `ListNodes`、`SearchNodes`、`Trace`、`GetNode`、`ReadContent`、
  `GetViewState`、`GetViewEntries` 和历史 `OpenView`。List/Search/Trace 使用
  `Limit=1` 或小输出预算，观察分页是否减少底层 catalog 读取。
- observation 的 read/scan 数值来自同一 fixture 上计时前的一次 representative
  preflight；计时期间 mailbox 只在计时结束后清空，不把观测消费成本混入时间。
  `B/op` 是每 op 累计分配，不是峰值 RSS；本阶段没有峰值内存、journal 增量或
  full transport delivery 证据。

## fixture 容量和正确性预检

| fixture | state records | historical cut   | content page |
| ------- | ------------: | ---------------- | ------------ |
| small   |            32 | 初始 publication | 1            |
| medium  |           256 | 初始 publication | 1            |
| near    |          1024 | 初始 publication | 1            |

预检确认：

1. `GetViewEntries` 返回完整且按 key 排序的 state；
2. `ListNodes` 的 page 1 返回 continuation，续页仍返回稳定顺序；
3. `SearchNodes` 返回 `Coverage=complete_layer`；
4. `Trace`、`GetNode`、`ReadContent`、`GetViewState` 返回与固定 View 绑定的结果；
5. 历史 View 在更新 publication 后仍返回旧 anchor 的完整 state。

这些预检使用真实 API，但 benchmark 仍只覆盖 content layer；Agent entities、
Knowledge selected view、typed context、真实 Unix delivery 和 reconnect 不在
本阶段范围内。

## 正式命令

```sh
gofmt -w engine/node_r20_benchmark_test.go
go test ./engine -run '^(TestHistoricalViewEntriesReturnsAuthenticatedCompleteState|TestNodeSearchExactSummaryCoverageHistoricalPagesAndAuthorization|TestNodeTraceDirectedScopePaginationDepthAndHistory|TestCursorNodeContentUsesSelectedAncestryUnlessExplicitAudit)$' -count=1
go test ./engine -run '^$' -bench '^BenchmarkNodeR20Queries' \
  -benchmem -benchtime=100ms -count=3 -cpu=1
```

第一条 `go test` 是 correctness preflight，第二条只负责 benchmark。正式样本在
Darwin/arm64 Apple M1 执行；benchmark 输出和 `ate-source-v2` 源码指纹随验证
批次保存。

## 当前判断

代码路径已经证明小页只限制输出 DTO：

- `ListNodes`、`SearchNodes` 和 `Trace` 在 page 1 前构造完整
  `nodeCatalog` 或 adjacency；
- `GetViewEntries` 是完整 state scan，超过限制返回错误而不是 partial page；
- `GetViewState` 走 point lookup，适合单 key 读取；
- `ReadContent` 返回 range，但仍需要完整 projection digest；
- continuation 续页会重新构造 catalog，当前没有持 anchor 的物化 iterator。

正式样本确认：List/Search/Trace 的 page 1 在 1024 records 时仍分别读取
约 2,172 个对象和 420,405 bytes；GetNode/ReadContent 也支付相同 catalog
读取，说明当前目标定位和 range 输出没有把分页前物化成本隔离掉。GetViewEntries
的 representative scan 随 state records 增长，GetViewState 保持点查规模。
后续应先区分 metadata-only list、详情按需读取和必须完整认证的关系查询，再
设计持 anchor iterator；不能通过跳过 complete layer、disclosure 或 digest
验证换取速度。

`1a9b5ac5ae14555e04d83f2da56673ea2fcfc2ef3722ea5aa2bae30feb9a410c`，
correctness preflight 和正式三次 benchmark 均退出 0。
