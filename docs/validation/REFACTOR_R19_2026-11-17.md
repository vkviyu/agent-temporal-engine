# R19 TaskTrace scope fan-out 基线验证

日期：2026-11-17。本阶段建立 TaskTrace scope、事件筛选、小页读取、
overview 共享祖先和 causal evidence 的第一阶段容量基线，不修改生产查询、
索引、分页 token 或权限实现，也不提交 Git。

## 范围和测量口径

- `BenchmarkTaskTraceR19Scope` 测量 immutable `taskTraceProfile.scope` 的
  deep、wide、shared topology，分别覆盖 warm projection 和 cold
  profile construction + scope。
- `BenchmarkTaskTraceR19EventFilterAndPage` 测量多个 scope key 合并事件流、
  milestone filter 和固定 32 条小页。它使用内存中的 metadata index，不测
  journal、对象解码、authorization 或 final delivery。
- `BenchmarkTaskTraceR19OverviewAndEvidence` 复用现有独立内存 fixture，测
  shared ancestry 在 1/32/128 selected events 下的 overview，以及多 agent
  causal path 的冷 evidence traversal。
- scope fixture 通过 `newTaskTraceProfile` 构造投影；跨 task parent 只用于保留
  `profile.scope` 的查询拓扑语义，故不调用 `EncodeRecordImage`。canonical
  record validation、durable publication 和恢复成本由其他阶段单独测量。
- benchmark 计时前完成 fixture 构造和语义预检，每项调用 `ReportAllocs`。
  `B/op` 是累计分配，不表示峰值 RSS；本阶段没有峰值内存、对象 IO 或 journal
  增量证据。

## correctness preflight

现有测试在 benchmark 前后提供语义对照：

1. `TestTaskTraceProfileScopeMatchesLedger` 验证 task/execution subtree、
   cross-task child、task key 去重和 cached topology 不被 scope 修改。
2. `TestTaskTraceOverviewSharesDeepAncestry` 验证共享祖先只被发现一次，
   page membership 和 condensed edge 保持。
3. `TestTaskTraceEvidenceCacheReusesWholePathAcrossPages` 验证 causal path
   跨页复用、页内只物化当前事件、cache eviction 后 continuation 仍可重建。
4. 新 fixture 检查 scope key 始终绑定固定 space/principal 且没有重复 key；
   benchmark 检查 page 和 evidence path 非空。

## benchmark 结果

正式命令：

```sh
gofmt -w engine/task_trace_r19_benchmark_test.go
go test ./engine -run 'TestTaskTraceProfileScopeMatchesLedger|TestTaskTraceOverviewSharesDeepAncestry|TestTaskTraceEvidenceCacheReusesWholePathAcrossPages' -count=1
go test ./engine -run '^$' -bench '^BenchmarkTaskTraceR19' \
  -benchmem -benchtime=100ms -count=3 -cpu=1
```

第一条命令是 correctness preflight，第二条只负责 benchmark。两条命令均在
Darwin/arm64 Apple M1 执行；正式输出和源码指纹在验证批次中保留。本报告只记录
稳定范围和代表性观察，避免把单次短样本当作机器无关 SLO。

| 测量                 | 代表性观察                                                                                                                                                                            |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| warm scope           | deep 32/256/1024 depth 约 11–14µs / 80–87µs / 0.35–0.39ms；wide 32/256/1024 width 约 11–13µs / 79–81µs / 0.35–0.37ms；shared 32/256/1024 width 约 5.6–5.8µs / 43–44µs / 0.205–0.209ms |
| cold profile + scope | deep 32/256/1024 约 38–39µs / 0.28–0.29ms / 1.27–1.53ms；wide 32/256/1024 约 31–32µs / 0.23–0.24ms / 0.97–1.01ms；shared 32/256/1024 约 17–32µs / 0.114–0.115ms / 0.50–0.54ms         |
| event filter/page    | 66 keys 约 0.27–0.35ms、514 keys 约 2.17–3.17ms；shared 259 keys 约 1.15–1.51ms。每页固定 32 条，覆盖 2/16 shared EventID、交错 LSN 和 duplicate suppression                          |
| overview             | ancestry 1025 下 page 1/32/128 约 0.48–0.58ms / 0.48ms / 0.51–0.66ms；小 page 仍承担接近完整 ancestry traversal                                                                       |
| causal evidence      | 约 2050 path events 的三种 fan-out 约 3.59–5.47ms，约 2.57MB/op 的累计分配（约 2.45MiB/op）；path event 数相同但 topology 会改变常数                                                  |

事件 filter/page 使用交错 LSN 的多个 stream，并包含跨 key 的共享 EventID，正式
样本同时覆盖 k-way merge 和 duplicate suppression。其成本同时受 scope key 数、
每个 key 的事件流长度、过滤命中密度和重复事件 fan-out 影响，不能仅按 indexed
event 总数线性外推。正式三次输出中的数值和源码指纹随验证批次保存，后续比较
必须重新执行相同命令。本批 `ate-source-v2` 起止源码指纹为
`f062935b0a7aec2da9a238b0c7484818271f54cfaea4cabb8e3f391e24739db6`，
benchmark 退出码为 0。

## 结论和后续边界

- R19 第一阶段测量完成，确认 scope 构造按 execution subtree 扩展，overview
  和 evidence 在 `Limit=1` 或小 page 下仍可能支付共享 ancestry/path 的完整发现成本。
- 当前没有机器无关的延迟 SLO，也没有证明独立 scope budget 或分段索引应立即
  接入 production path；本阶段不新增第二份 topology authority。
- 暂不修改 scope 算法、事件索引或 continuation。后续若规模要求继续增长，应
  先分别测 R20 的 Node/View/Content 物化和 R24 的峰值内存，再决定是否需要
  独立的 scope budget。任何 scope cache 或分段索引都必须绑定 principal、
  historical anchor 和 authenticated profile root，且 query-only 不能制造
  Task/Execution。
